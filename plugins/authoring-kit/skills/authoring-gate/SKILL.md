# authoring-gate (품질 게이트)

**판정만 하는 게 아니라 통과시킬 때까지 끌고 간다.** 채점 → 보완 → 재채점을 최대 3라운드 돈다.

## 동작 순서

### 1. 대상과 규칙 확정

파일 경로를 받고, `--spec` 이 없으면 프로젝트의 spec 목록에서 고르거나 묻는다.

```bash
python3 ${CLAUDE_PLUGIN_ROOT}/scripts/authoring.py resolve \
  --voice <spec의 voice> --spec <spec-id> --profile worker
```

채점 기준은 **해석 결과 하나**다. 루브릭·voice·spec 을 각각 따로 읽지 않는다 —
그러면 라운드마다 기준이 흔들린다.

### 2. 채점

**공통 항목**(A 독자 이해 · E 정확성 · F 문체 · V voice 준수)은 `QUALITY_RUBRIC.md` 에서,
**글 종류별 항목**(B 깊이 · C 구성 · D 다관점/금기 · G 기술 건전성)은 spec 의 `principles[]` 에서 온다.

각 항목을 **충족 / 미흡 / 해당없음**으로 판정한다.

> **평가는 반드시 본문에서 근거를 인용해서 한다. 추측 금지.**
> 인용이 안 나오면 그 항목은 **미흡**이다. 이게 채점의 뿌리다.

기계로 세는 것은 기계에 맡긴다:

```bash
python3 ${CLAUDE_PLUGIN_ROOT}/scripts/scan_ai_style.py "<파일>"                    # 문체 등급
python3 ${CLAUDE_PLUGIN_ROOT}/scripts/lint_placeholders.py check "<파일>" --stage final
```

- 문체 등급 합격선 **B 이상**. **면제된 코드는 세지 않는다**(해석 결과의 면제 목록 확인).
- `--stage final` 에서 미해결 슬롯·집필 지시·마커가 0이어야 한다.
- 빌드·테스트는 `paths.json` 의 `commands` 로 돌린다. **명령을 스킬에 박지 않는다.**

### 3. 분량 확인 — 10배를 넘으면 멈춘다

```bash
python3 ${CLAUDE_PLUGIN_ROOT}/scripts/golden.py measure <파일> --spec <id> --project <dir> --voice <id>
```

`content.prose_chars` 를 **참조 기준**과 비교한다(골든셋 기준값 → `paths.json` 의 `exemplars` →
같은 spec 의 최근 산출물 순). **10배를 넘으면 판정을 끝내지 말고 사용자에게 묻는다** —
무엇이 늘었는지 함께 보여 주고, "그대로 진행"을 고르면 통과로 처리한다.

10배 이하면 보고만 한다. 명세가 요구한 항목을 채우면 길어지는 것이 정상이다.
비교 대상이 없으면 이 검사는 건너뛴다.

### 4. 판정

**PASS = MUST 전부 충족 + SHOULD 미흡 ≤ 2 + IF-APPLICABLE 은 충족 또는 정당한 생략 메모.**

IF-APPLICABLE 을 생략했으면 **왜 뺐는지가 보고에 있어야** 충족이다.
생략 사유는 **보고에만** 남는다 — 독자용 문서 본문에 "해당 없음" 을 남기면 그 자체가 위반이다.

### 5. 보완 루프 (최대 3라운드)

FAIL 이면 미흡 항목을 고치고 재채점한다.

- **단순 교정**(약어 풀어쓰기, 근거 한 줄 추가, 어미 변주)은 직접 고친다.
- **새로 써야 하는 분량**이면 `authoring-write` 의 집필 단계로 되돌린다.
- 고칠 때 **활성 voice 를 깎지 않는다.** 면제된 코드를 "고쳐서" 카운터를 내리는 것은 실패다.
- **3라운드에도 MUST 가 남으면 멈추고 사람에게 넘긴다.** 라운드를 소진했다고 통과시키지 않는다.

### 6. 보고

```
MUST          통과 X / 전체 Y
SHOULD        미흡 N개
IF-APPLICABLE 충족 / 정당한 생략(사유 포함) / 미흡
문체 등급      A~D  (면제 코드 제외)
보완 라운드    N / 3
최종          PASS | FAIL — 보완 필요
```

FAIL 이면 항목별로 **코드 · 인용한 본문 근거 · 어디를 어떻게 고칠지**를 함께 낸다.
생략한 조건부 항목과 사유를 반드시 포함한다.

## 채점을 위임할 때

본문이 길면 `Agent` 로 채점 워커를 띄운다. 프롬프트에 담을 것:

- "**먼저 `authoring-method` 를 호출**해 채점 기준 전문을 로드하라."
- 본문 전체를 메인 컨텍스트에 올리지 말고 워커가 읽게 한다.
- 워커는 **판정 결과와 인용 근거만** 반환한다.

## 주의

- **자동 통과 없음.** 판단이 서지 않는 항목은 미흡으로 두고 사람에게 묻는다.
- 한 항목을 두 갈래에서 중복 채점하지 않는다. 문체는 voice 준수(V)와 기계 리듬 등급으로 각각 재고,
  번역투는 공통 원칙의 `grammar` 코드로만 낸다.
- 외부 검토(codex/agy)는 이 스킬의 소관이 아니다 — `authoring-write` 가 앞 단계에서 돌린다.
  실패했으면 그 사실을 보고에 반영한다.
