# authoring-voice (퍼소나 등록)

한 저자·퍼소나가 **어떻게 말하는가**를 등록한다. 공통 원칙과 섞이지 않게 축으로 나눠 받는다.

## voice 가 소유하는 축 — 이것만 쓴다

| 축 | 무엇 |
| --- | --- |
| `register` | 종결 톤 · 경어체 · 격식. 한 글 안에서 톤을 섞는지, 섞는다면 어디까지 |
| `rhythm` | 문장 호흡 · 길이 분포 · 전개 보폭 |
| `device` | 독자 장치 — 호명 · 우화 · 도식 · 기억법 · 확인 질문 등 |
| `lexicon` | 어휘군 · 인용 습관 · 연결어 |

**여기 없는 것은 voice 가 정하지 않는다.** 어떤 항목이 어떤 순서로 필요한지는 글 명세(L2)가,
사실·문장·박자는 공통 원칙(L0)이 정한다. 넘어서면 `validate` 가 축 위반으로 막는다.

## 동작 순서

### 1. 어디서 뽑을지 정한다

세 경로가 있고, 정확도 순이다.

1. **기존 글에서 역추출** — 그 퍼소나로 이미 쓴 글이 있을 때. 가장 정확하다.
2. **사용자 구술** — 새로 만드는 퍼소나. 아래 인터뷰로 받는다.
3. **다른 voice 에서 갈라내기** — 기존 voice 가 실은 둘이었을 때.

### 2. 역추출할 때 — 모수를 먼저 의심한다

**"그 퍼소나로 쓴 글"이 전부 같은 목소리라는 보장이 없다.** 파이프라인을 우회해 손으로 쓴 글,
퍼소나 도입 전에 쓴 글, 다른 사람이 손댄 글이 섞여 있으면 **드리프트가 새 표준으로 굳는다.**

1. **모수 선별** — 퍼소나가 적용되지 않은 것으로 알려진 글은 **뺀다.**
   프로젝트 메모리·커밋 로그·게이트 보고에 그런 기록이 있는지 먼저 본다.
2. **일관성 검증** — 시리즈·시기별로 2~3편씩 샘플링해 종결·호흡·장치 특성을 비교한다.
   `scan_ai_style.py` 지표도 함께 본다. **편차가 크면 그 사실 자체를 보고하고**
   어느 쪽을 기준으로 삼을지 사용자에게 묻는다.
3. **초안은 `status: "draft"`** 로 저장한다. 승인 전에는 `defined` 로 올리지 않는다.

### 3. 인터뷰 (`AskUserQuestion`)

- **말투** — 종결을 어떻게 맺는가. 글 종류에 따라 바뀌는가. 섞어도 되는가, 되면 얼마나.
- **호흡** — 긴 문장이 기본인가 짧은 단계가 기본인가. 강타는 어디에 놓는가.
- **장치** — 독자를 끌어들이는 고유한 방법. 예문과 함께 받는다.
- **어휘** — 즐겨 쓰는 어휘군·연결어·인용 습관. **하지 않는 표현**도 함께.
- **금지** — 이 퍼소나가 절대 하지 않는 것.

각 항목은 **예문 없이 넘어가지 않는다.** 추상적 형용사("친근하게")만으로는 재현되지 않는다.

### 4. 면제(waiver) 선언 — 신중하게

공통 원칙의 기계 리듬 탐지가 이 퍼소나의 색을 증상으로 오인한다면, 코드별로 면제를 선언한다.

```json
{ "code": "R2", "target": "L0:machine-rhythm",
  "reason": "만연체가 기본 호흡이다",
  "limit": "종속절 4개 이상이면 waiver 해제" }
```

- **`reason` 없는 면제는 거부된다.** 조용한 면제는 만들지 않는다.
- **`evidence`·`grammar`·`comprehension` 은 면제할 수 없다**(hard floor). 시도하면 `validate` 가 막는다.
- **`limit` 을 반드시 적는다** — 면제에도 한계가 있어야 한다. 무제한 면제는 규칙을 지우는 것이다.
- 면제가 필요 없으면 비워 둔다. **다른 퍼소나의 면제를 물려받지 않는 것이 이 분리의 요점이다.**

### 5. 저장과 검증

```
~/.claude/authoring/voices/<id>/voice.json    기계 판독 — 축·파라미터·면제
~/.claude/authoring/voices/<id>/voice.md      사람·에이전트 판독 — 규칙 N개(예문 포함) + 금지 목록
```

`voice.md` 형식은 **"문체 규칙 N개(각 규칙 + 예문) + 금지 목록"** 이다. 두 프로젝트에서 검증된 형식이다.

```bash
python3 ${CLAUDE_PLUGIN_ROOT}/scripts/authoring.py validate --voice <id>
```

### 6. 분리 확인 — 등록의 합격 판정

```bash
python3 ${CLAUDE_PLUGIN_ROOT}/scripts/authoring.py resolve --voice <id> --profile worker
```

출력에 **다른 퍼소나의 문체 표지가 하나도 없어야** 한다. 있으면 그 규칙이 잘못된 층에 있는 것이다 —
공통 원칙(L0) 문서에 특정 저자 얘기가 남아 있는지부터 본다.

### 7. 종료 보고

- 저장 경로 · `status`(defined/draft) · 축별 요약 · 면제 수와 사유.
- 역추출이었다면 **모수에서 뺀 글과 그 이유**, 시리즈 간 편차.
- `used_by` 에 어느 프로젝트가 이 voice 를 쓰는지 기록한다.

## 주의

- **voice 는 프로젝트를 넘나든다.** 같은 퍼소나를 프로젝트마다 따로 만들지 마라 —
  그게 지금 고치고 있는 복제 문제다. 이미 있으면 `used_by` 에 프로젝트를 추가한다.
- 글 종류별 농도(어디서 진하게, 어디서 절제)는 **voice 가 아니라 spec** 이 정한다.
- 사람 저자의 문체를 AI 퍼소나에 그대로 적용하지 않는다. 다른 저자면 다른 voice 다.
