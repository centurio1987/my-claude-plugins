# voice 역추출 — 모수를 먼저 의심한다

이미 쓴 글에서 문체를 뽑는 것은 백지 인터뷰보다 정확하다. **단, 뽑는 대상이 맞을 때만 그렇다.**

> **가장 큰 위험은 "그 퍼소나로 쓴 글"이 전부 같은 목소리라는 가정이다.**
> 파이프라인을 우회해 손으로 쓴 글, 퍼소나 도입 전에 쓴 글, 다른 사람이 손댄 글이 섞여 있으면
> **드리프트가 새 표준으로 굳는다.** 한 번 굳으면 그 뒤로 쓰는 모든 글이 그 방향으로 간다.

## 1. 모수 선별 — 뺄 것을 먼저 찾는다

후보 글을 모으기 전에 **뺄 글**부터 찾는다. 단서가 남아 있는 곳:

| 어디 | 무엇을 찾나 |
| --- | --- |
| 프로젝트 메모리 | "퍼소나가 적용되지 않았다", "손집필했다" 류의 기록 |
| 커밋 로그 | 집필 스킬을 안 거친 커밋, 대량 일괄 수정 |
| 품질 게이트 보고 | 문체 항목이 미흡으로 남은 채 발행된 글 |
| 저자 표기 이력 | 나중에 저자를 바꿔 단 글 |

**뺀 글과 이유를 `source.corpus.excluded` 에 적는다.** 나중에 "왜 이 문체가 이렇게 정의됐나"를
되짚을 유일한 단서다.

## 2. 일관성 검증 — 남은 모수가 한 목소리인가

시리즈·시기별로 **2~3편씩 샘플링**해 비교한다.

```bash
python3 ${CLAUDE_PLUGIN_ROOT}/scripts/scan_ai_style.py <파일> --json
```

볼 것:

| 항목 | 어떻게 |
| --- | --- |
| **종결** | 어미 분포. 격식체 통일인가, 평서체인가, 섞는가 |
| **호흡** | 문장 길이 분포. 긴 문장이 기본인가 짧은 단계가 기본인가 |
| **장치** | 도식·질문·호명·인용이 어디에 얼마나 |
| **어휘** | 반복되는 연결어·어휘군 |
| **기계 리듬 지표** | 쉼표 밀도·어미 연속·불릿 비중 |

**편차가 크면 그 사실 자체를 보고한다.** 평균을 내지 말고 사용자에게 묻는다:

> "OSI 시리즈와 VPN 시리즈의 종결 분포가 다릅니다. 어느 쪽을 이 퍼소나의 기준으로 삼을까요?"

평균은 **어느 글과도 닮지 않은 문체**를 만든다. 그건 재현이 아니다.

## 3. 갈래별로 뽑는다

관찰한 것을 네 항목에 나눠 담는다. **관찰과 지침을 섞지 않는다** —
"이렇게 쓴다"(관찰)와 "이렇게 써야 한다"(지침)는 다르다. 역추출은 관찰이다.

- **`register`** — 종결 톤. 글 종류에 따라 바뀌면 그 조건까지.
- **`rhythm`** — 기본 호흡과 강타 자리. "긴 문장이 기본이고 강조에서 끊는다" 식으로.
- **`device`** — 반복해서 나타나는 장치를 kebab-case 로 나열.
  **본문에서 실제로 센다** — 한두 번 나온 것은 장치가 아니다.
- **`lexicon`** — 즐겨 쓰는 어휘·연결어. **하지 않는 표현**도 함께 관찰한다.

**각 항목에 원문 예문을 붙인다.** 추상적 형용사("친근하게")만으로는 재현되지 않는다.
`voice.md` 의 규칙마다 예문이 하나씩 붙어 있어야 한다.

## 4. 면제 후보를 찾는다

기계 리듬 스캐너가 이 퍼소나의 색을 **증상으로 오인**하는 곳이 있는지 본다.

```bash
python3 ${CLAUDE_PLUGIN_ROOT}/scripts/scan_ai_style.py <대표 글>
```

적발된 코드를 하나씩 보고 판단한다:

- **정말 고쳐야 하는가** → 면제하지 않는다.
- **이 퍼소나가 의도한 것인가** → 면제 후보. `reason` 과 `limit` 을 함께 정한다.

> 면제를 남발하면 규칙이 사라진다. **면제는 "이 코드는 이 저자에게 증상이 아니다"를 증명할 수 있을 때만** 단다.
> 대표 글 여러 편에서 같은 코드가 걸리는데 읽어 보면 잘 쓴 대목이라면, 그때가 면제할 때다.

`evidence`·`grammar`·`comprehension` 은 면제 대상이 아니다. 시도하면 `validate` 가 막는다.

## 5. 초안은 `draft` 로 저장한다

```json
{ "status": "draft" }
```

**사람 승인 전에는 `defined` 로 올리지 않는다.** 게이트는 `draft` voice 로 집필하면 경고를 낸다.

승인 요청 시 보여 줄 것:

- 갈래별 요약과 **근거가 된 예문**.
- 모수: 넣은 글과 **뺀 글 + 이유**.
- 시리즈 간 편차가 있었다면 그 사실과 어느 쪽을 골랐는지.
- 면제 후보와 각각의 사유.

## 6. 분리 확인

```bash
python3 ${CLAUDE_PLUGIN_ROOT}/scripts/authoring.py resolve --voice <새 id> --profile worker
```

출력에 **다른 퍼소나의 문체 표지가 하나도 없어야** 한다.
있으면 그 규칙이 잘못된 층에 있는 것이다 — 공통 원칙 문서에 특정 저자 얘기가 남았는지부터 본다.

`fixtures/test_layer_separation.py` 에 새 voice 를 추가해 두면 이후 회귀에서 자동으로 검사된다.

## 흔한 실패

| 증상 | 원인 |
| --- | --- |
| 뽑은 문체가 어느 글과도 안 닮았다 | 이질적인 모수를 평균 냄 (§2) |
| 규칙이 추상적이라 재현이 안 된다 | 예문 없이 형용사만 적음 (§3) |
| 면제가 너무 많아 규칙이 무의미하다 | 적발을 전부 면제로 처리 (§4) |
| 다른 퍼소나 글에서도 이 문체가 나온다 | 공통 원칙에 저자 문체가 남아 있음 (§6) |
