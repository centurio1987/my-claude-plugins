# 외부 검토로 나가기 전 치환 규칙 — **구조적 패턴만.**  <perl 정규식><탭><치환 토큰>
#
# 이 파일은 PUBLIC 저장소에 산다. 그래서 **실명·핸들 같은 고유 리터럴을 여기 두지 않는다** —
# 가리려던 것을 프로파일 자체가 공개해 버리기 때문이다. 고유 리터럴은 PRIVATE 레지스트리
# (`$AUTHORING_KIT_HOME/redact/resume-pii.txt`)나 프로젝트 계층에 두고, 실행 시 이어 붙인다.
#
# 원칙: **구조와 서사는 남기고 식별자만 가린다.** 다 가리면 검토가 무의미해진다 —
# "이 경력 서술이 설득력 있는가"를 물으려면 경력 내용은 남아 있어야 한다.
#
# **적용 순서가 중요하다 — 넓은 패턴을 먼저, 좁은 리터럴을 나중에.**
# 핸들을 먼저 치환하면 `someone@gmail.com` 이 `[HANDLE]@gmail.com` 이 되고,
# 그 뒤 이메일 정규식(`[\w.+-]+@…`)은 대괄호를 못 물어 `@gmail.com` 이 그대로 나간다.
# 계층 순서(플러그인 → 사용자 → 프로젝트)가 곧 이 순서다.
#
# 주의: perl `s/…/…/g` 로 적용되므로 패턴 안의 `/` 는 `\/` 로 이스케이프해야 한다.
# 주석(#)과 빈 줄은 무시한다.

# ── 구조적 식별자 (넓은 정규식) ──
[\w.+-]+@[\w-]+\.[\w.]+	[EMAIL]
# 국제 표기를 먼저 — `+82 10-…` 은 앞의 0 이 빠져서 국내 패턴(`01x`)에 안 걸린다.
# 이력서가 실제로 이 표기를 쓰는데 국내 패턴만 두었더니 전화번호가 그대로 나갔다.
\+?82[-. ]?1[016-9][-. ]?\d{3,4}[-. ]?\d{4}	[PHONE]
\b01[016-9][-. ]?\d{3,4}[-. ]?\d{4}\b	[PHONE]
\b\d{6}-\d{7}\b	[RRN]
