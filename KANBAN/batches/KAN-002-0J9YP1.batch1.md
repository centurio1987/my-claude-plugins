## 1. 작업 패키지

### WP1 · `S1` 레지스트리 — 층별 사용자 범주

`style_registry.py` 의 빈 층·정리·유효값·검증·렌더에 `directives.categories` 를 넣는다.

**완료 기준**: 사용자 범주를 쓴 지시가 저장되고, 미리보기와 게이트 항목에 범주 이름과 판정 질문이 실린다. 잘못된 범주(없는 상위·겹치는 id·빈 이름·축 기재·쓰는 지시가 있는 채 삭제)는 저장 전에 거부된다.

### WP2 · `S2` 서버 — 병합된 분류를 내주고 전역 저장을 지킨다

**완료 기준**: `/api/effective` 응답에 병합된 분류가 실리고, voice 가 쓰는 전역 범주를 지운 전역 저장이 거부된다.

### WP3 · `S3` 편집기 — 범주 추가·수정·삭제

**완료 기준**: 브라우저에서 범주를 만들고 항목에 골라 저장한 뒤 새로고침해도 유지된다. 폰 너비(390px)에서 가로 스크롤이 없다.

### WP4 · `S4` 검사·문서·판올림

**완료 기준**: `test_style.py` 에 사용자 범주 검사가 들어가 전부 통과하고, `STYLE_SCHEMA.md`·`authoring-style` 스킬이 새 필드를 설명하며, 판이 0.4.1 이다.

## 2. 의존과 순서

S1 → S2 → S3 는 순서가 있다. S2 는 S1 의 유효값 모양을, S3 는 S2 의 응답 모양을 쓴다. S4 의 검사는 S1·S2 가 끝나면 쓸 수 있어 S3 과 겹칠 수 있다.

## 3. 리스크

- 편집기(`ui/style-editor.html`)는 입력 중 다시 그리기를 막는 덮어쓰기가 있어, 범주 폼을 넣을 때 커서가 튀는 문제가 다시 날 수 있다.
- 전역 저장 때 voice 층을 함께 검사하므로 voice 가 많으면 저장이 느려질 수 있다. 지금은 voice 5개이고 속도는 확인 안 함.
